## 一、产品概述

本设备是一台**网络电台转发器**：通过 WiFi 接收互联网 MP3/AAC 音频流，实时解码后经蓝牙转发到耳机/音箱播放。支持串口命令、CLI 客户端、GUI 客户端三种控制方式。

### 三种控制方式

| 方式 | 通道 | 用途 |
|------|------|------|
| USB 串口命令 | USB 线连电脑 | 开发调试、配置 WiFi、切台调音量 |
| CLI 客户端 | Python + pyserial | 脚本自动化、JSON 输出、MCP 集成 |
| GUI 客户端 | Python + PyQt5 | 图形界面操作、状态监控 |
| AVRCP 耳机按键 | 蓝牙耳机媒体键 | 播放/暂停/上下曲/音量 |

### 蓝牙角色

| 角色 | 协议 | 方向 | 说明 |
|------|------|------|------|
| A2DP Source | 音频流 | ESP32 → 耳机 | 主动连接耳机发音频 |

## 二、快速开始（5 步出声）

1. **配置 WiFi**：用 USB 线连电脑，串口终端（115200）发 `wif 你的WiFi名 你的WiFi密码`，重启
2. **连接耳机**：耳机开机进入配对模式，ESP32 自动扫描连接（60 秒内）
3. **自动播放**：连接成功后自动播放默认电台（上海 LoveRadio）
4. **切台**：串口发 `list` 看电台列表，发 `play 5` 切到 5 号台
5. **调音量**：发 `vol 60` 调到 60%

## 三、软件命令大全

### 3.1 命令输入方式

命令通过 **USB 串口**输入：USB 线连电脑，串口终端（115200bps），换行模式选 NL 或 CRLF。

> 命令以 **换行符 `\n`** 触发解析。串口终端的回车需配置为发 `\n` 或 `\r\n`（Arduino IDE 选"NL"，PuTTY 配 Line feed）。
> 前导空格/Tab 会被自动跳过（v1.4.0）。

### 支持的音频格式

| 格式 | 支持 | 说明 |
|------|------|------|
| HTTP MP3 | ✅ | 蜻蜓 FM 等在线 MP3 流 |
| HTTP AAC | ✅ | 喜马拉雅 HLS AAC、国际 AAC 流 |
| HTTP m3u8/HLS | ✅ | CNR/CRI TS 容器 HLS 流（TsDemux 解复用） |
| HTTPS | ❌ | 暂不支持（mbedTLS in buffer 5120B 硬限制） |

### 3.2 播放控制命令

| 命令 | 格式 | 说明 | 示例 |
|------|------|------|------|
| `play` | `play [序号 \| URL]` | 播放指定序号电台，或直接播放 URL | `play 0` / `play http://...` |
| `next` | `next` | 播放下一个电台 | `next` |
| `prev` | `prev` | 播放前一个电台 | `prev` |
| `pause` | `pause` | 播放/暂停切换（软暂停，保持蓝牙连接） | `pause` |
| `stop` | `stop` | 停止播放 | `stop` |
| `vol` | `vol [0-100]` | 设置音量（0-100） | `vol 60` |

### 3.3 电台管理命令

| 命令 | 格式 | 说明 | 示例 |
|------|------|------|------|
| `list` | `list [分类]` | 显示电台列表（可选分类过滤） | `list 音乐` |
| `save` | `save [名称] [URL] [分类]` | 保存自定义电台（最多 50 个） | `save 我的电台 http://example.com/stream.mp3 自定义` |
| `del` | `del [序号]` | 删除自定义电台（只能删自定义） | `del 71` |
| `test` | `test [序号]` | 测试电台 URL 可访问性 | `test 5` |

### 3.4 蓝牙控制命令

| 命令 | 格式 | 说明 | 适用场景 |
|------|------|------|---------|
| `scan` | `scan` | 重新扫描蓝牙设备 | 换耳机、搜索不到设备 |
| `clear` | `clear` | 清除所有蓝牙配对 + 记忆直连地址 | 换耳机、配对异常 |
| `avrcdiag` | `avrcdiag` | AVRCP 诊断：检测耳机按键发什么事件 | 耳机按键不响应时诊断 |

### 3.5 系统命令

| 命令 | 格式 | 说明 |
|------|------|------|
| `status` | `status` | 显示当前状态（电台/解码/采样率/音量/蓝牙/缓冲/License 等） |
| `wif` | `wif [SSID] [密码]` | 修改 WiFi 凭证（重启生效） |
| `lic` | `lic [激活码]` | 查看授权状态（无参）或激活授权（有参） |
| `clearlic` | `clearlic` | 清除授权（播放将锁定） |
| `restart` | `restart` | 重启设备 |
| `verbose` | `verbose` | 事件日志开关（开/关调试输出，NVS 记忆） |
| `pair` | `pair` | 进入蓝牙配对模式（暂停 A2DP，可被搜索） |
| `normal` | `normal` | 恢复 A2DP 正常模式（配对完成后用） |
| `help` | `help` | 显示命令帮助 |

### 3.6 CLI 客户端（v1.4.1 新增）

除了串口终端，还可以用 Python CLI 客户端操作设备：

```bash
cd tools/cli
pip install -r requirements.txt

# 列出可用串口
python esp32_cli.py ports

# 交互模式
python esp32_cli.py --port COM10

# 单命令
python esp32_cli.py --port COM10 status
python esp32_cli.py --port COM10 play 0
python esp32_cli.py --port COM10 vol 50

# JSON 输出（方便脚本/MCP 调用）
python esp32_cli.py --port COM10 status --json
python esp32_cli.py --port COM10 stations --json

# 持续监控
python esp32_cli.py --port COM10 --watch
```

## 四、A2DP 蓝牙音频操作流程

### 4.1 首次连接蓝牙耳机/音箱

**前提**：WiFi 已配置，ESP32 已开机。

1. 蓝牙耳机/音箱**开机并进入配对模式**（通常长按电源键或配对键，指示灯快闪）
2. ESP32 上电后自动扫描，发现耳机后自动连接（60 秒超时）
3. 连接成功日志：`[A2DP连接] Connected`
4. 自动播放默认电台

> 首次连接后，ESP32 记住耳机地址，下次开机自动回连。

### 4.2 记忆直连（日常开机即连）

首次配对成功后，**日常使用无需任何操作**：

1. ESP32 开机 → 自动回连上次耳机（无需耳机进配对模式，只要耳机开机且未被占用）
2. 回连失败重试 8 次后回退扫描模式
3. 连接成功后自动播放上次电台和音量

### 4.3 更换蓝牙耳机

```
USB 串口发: clear
→ 清除所有配对 + 记忆直连地址
→ ESP32 自动重新扫描
→ 新耳机进入配对模式
→ 自动连接新耳机
```

### 4.4 A2DP 连接故障处理

| 故障现象 | 原因 | 解决 |
|---------|------|------|
| 反复 Connecting→Disconnected | 配对密钥过期/stale bond | `clear` 清配对，耳机重新进配对模式，`scan` |
| 60 秒未连接 | 耳机未进配对模式 / 被其他设备占用 | 耳机进配对模式，`scan` |
| 连上但无声 | 音量为 0 / 电台源断供 | `vol 50` 调音量，`next` 换台 |
| 播放卡顿 | 网络不稳定 | 检查 WiFi 信号；已有 256KB 网络缓冲 |

## 六、AVRCP 耳机按键控制

蓝牙耳机/音箱/车机的媒体按键通过 AVRCP 协议控制 ESP32：

| 耳机按键 | 固件动作 |
|---------|---------|
| 播放 ▶ | 恢复播放（暂停后） |
| 暂停 ⏸ | 软暂停（停解码+清缓冲，保持蓝牙连接） |
| 下一曲 ▶▶ | 切换下一个电台 |
| 上一曲 ◀◀ | 切换上一个电台 |
| 停止 ■ | 停止播放 |
| 音量+ | 音量 +10 |
| 音量- | 音量 -10 |

> **注意**：
> - 按键转发行为取决于耳机固件，不同设备有差异
> - 很多耳机的音量键是**硬件直控**（直接调耳机 DAC），不发 AVRCP，ESP32 收不到。这类耳机用 `vol` 命令调音量
> - 暂停为"软暂停"：停止解码并清空 PCM 缓冲，但保持 A2DP 连接；恢复时重新拉流（有几秒延迟）

## 七、常见问题

### Q1：开机后耳机不自动连接？
A：确认耳机开机且未被其他设备占用。USB 串口发 `status` 看蓝牙状态。若显示未连接，发 `scan` 重新扫描。若仍不行，`clear` 清配对重来。

### Q2：耳机音量键没反应？
A：很多耳机的音量键是硬件直控（直接调 DAC 增益），不发 AVRCP，ESP32 收不到。诊断方法：USB 串口发 `avrcdiag`，按音量键看日志：
- 有 `[AVRCP诊断]` 事件 → 耳机发了 AVRCP，把事件号告诉我加支持
- 无任何日志 → 硬件直控，用 `vol` 命令或 GPIO14 物理按键调 ESP32 端音量

> 注：耳机端音量（硬件直控）和 ESP32 端音量（`vol` 命令）是两层叠加，互不影响。

### Q3：电台播放速度快或音调不对？
A：v1.1.0 已修复采样率问题（32k→44.1k 重采样，48k 直发）。若仍异常，发 `status` 看当前电台，`test` 测试可访问性。

### Q4：WiFi 改了密码怎么更新？
A：USB 串口发 `wif 新WiFi名 新密码`，重启生效。

### Q5：某些电台（如央广/国广）播放卡顿？
A：v1.4.0 新增 TsDemux 支持 CNR/CRI TS 容器 HLS 流。若仍卡顿，可能是网络不稳定或 satellitepull.cnr.cn CDN 不响应段下载（已知限制）。

### Q6：为什么无法播放 HTTPS 电台？
A：v1.4.0 暂不支持 HTTPS（mbedTLS in buffer 5120B 硬限制），请使用 HTTP 源。部分央广/国广源提供 HTTP 备选 URL。

### Q7：段边界偶发跳帧？
A：v1.4.0 已尽量消除，但 TS 容器 HLS 流在段边界处偶发跳帧，无法完全消除。
