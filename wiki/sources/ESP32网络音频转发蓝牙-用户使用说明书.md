# ESP32 网络音频转发蓝牙 — 用户使用说明书

> 这页是原始资料摘要：[[ESP32网络音频转发蓝牙设备]] v1.4.1 固件的用户操作手册（命令大全、A2DP 流程、AVRCP 耳机按键、FAQ）。

## 资料讲什么

`raw/用户使用说明书.md` 是 v1.4.1 固件（文档日期 2026-08-23）面向最终用户的操作手册，作者陈志明（电话 13654132703，微信 tsearcher）。提供三种控制方式：USB 串口命令、Python CLI 客户端、PyQt5 GUI 客户端；另含 AVRCP 耳机按键辅助控制。

> ⚠️ **PSRAM 描述分歧**：本资料声明"4MB Flash + 4MB PSRAM"，与 [[ESP32网络音频转发蓝牙-软件说明书]]（声明 4MB Flash + 8MB PSRAM）以及 [[ESP32网络音频转发蓝牙设备]]（4MB PSRAM）不一致。按 AGENTS.md 章法，并排放着，注明出处与日期，等用户裁断。

## 三种控制方式

| 方式 | 通道 | 用途 |
|------|------|------|
| USB 串口命令 | USB 线连电脑（115200bps） | 开发调试、配置 WiFi、切台调音量 |
| CLI 客户端 | Python + pyserial | 脚本自动化、JSON 输出、MCP 集成 |
| GUI 客户端 | Python + PyQt5 | 图形界面操作、状态监控 |
| AVRCP 耳机按键 | 蓝牙耳机媒体键 | 播放/暂停/上下曲/音量 |

蓝牙角色：A2DP Source — ESP32 → 耳机（主动连接耳机发音频）。

## 快速开始（5 步出声）

1. **配置 WiFi**：USB 串口发 `wif 你的WiFi名 你的WiFi密码`，重启。
2. **连接耳机**：耳机进入配对模式，ESP32 自动扫描连接（60 秒超时）。
3. **自动播放**：连接成功后自动播放默认电台。
4. **切台**：串口发 `list` 看电台列表，发 `play 5` 切到 5 号台。
5. **调音量**：发 `vol 60` 调到 60%。

## 命令输入约定

- 命令以换行符 `\n` 触发；终端配置发 `\n` 或 `\r\n`（Arduino IDE 选 NL、PuTTY 配 Line feed）。
- 前导空格/Tab 自动跳过（v1.4.0 行为）。

## 命令分类速查

### 播放控制
| 命令 | 格式 | 说明 |
|------|------|------|
| `play` | `play [序号 \| URL]` | 播放指定序号，或直接播放 URL |
| `next` / `prev` | `next` / `prev` | 上一/下一电台 |
| `pause` | `pause` | 软暂停（停解码 + flush，保持蓝牙连接） |
| `stop` | `stop` | 停止播放 |
| `vol` | `vol [0-100]` | 音量调节 |

### 电台管理
| 命令 | 格式 | 说明 |
|------|------|------|
| `list` | `list [分类]` | 显示电台列表（可选分类过滤） |
| `save` | `save [名称] [URL] [分类]` | 保存自定义电台（最多 50 个） |
| `del` | `del [序号]` | 删除自定义电台 |
| `test` | `test [序号]` | 测试 URL 可访问性 |

### 蓝牙控制
| 命令 | 说明 |
|------|------|
| `scan` | 重新扫描蓝牙设备 |
| `clear` | 清除所有配对 + 记忆直连地址（换耳机时用） |
| `avrcdiag` | AVRCP 诊断模式（检测耳机按键发什么事件） |
| `pair` | 进入配对模式（暂停 A2DP，可被搜索发现） |
| `normal` | 恢复 A2DP 正常模式（配对完成后用） |

### 系统命令
| 命令 | 说明 |
|------|------|
| `status` | 显示当前状态（含授权） |
| `wif [SSID] [密码]` | 修改 WiFi 凭证（重启生效） |
| `lic [激活码]` | 查看/激活授权 |
| `clearlic` | 清除授权（播放锁定） |
| `restart` | 重启设备 |
| `verbose` | 事件日志开关（NVS 持久化） |
| `help` | 显示命令帮助 |

## CLI 客户端示例（v1.4.1 新增）

```bash
cd tools/cli
pip install -r requirements.txt

python esp32_cli.py ports                            # 列出可用串口
python esp32_cli.py --port COM10                     # 交互模式
python esp32_cli.py --port COM10 status              # 单命令
python esp32_cli.py --port COM10 status --json       # JSON 输出（脚本/MCP 用）
python esp32_cli.py --port COM10 --watch             # 持续监控
```

依赖：`pyserial>=3.5`；GUI 客户端额外需要 `PyQt5>=5.15`。

## A2DP 连接故障处理

| 现象 | 原因 | 处理 |
|------|------|------|
| 反复 Connecting→Disconnected | 配对密钥过期 / stale bond | `clear` 清配对，耳机重进配对模式，`scan` |
| 60 秒未连接 | 耳机未进配对模式 / 被其他设备占用 | 耳机进配对模式，`scan` |
| 连上但无声 | 音量为 0 / 电台源断供 | `vol 50` 调音量，`next` 换台 |
| 播放卡顿 | 网络不稳定 | 检查 WiFi 信号（已有 256KB 网络缓冲） |

> ⚠️ **网络缓冲容量分歧**：本页 FAQ 写"已有 256KB 网络缓冲"，但 [[ESP32网络音频转发蓝牙-软件说明书]] 与 [[ESP32网络音频转发蓝牙设备]] 均写 NET_BUF_SIZE = 384KB。可能是 v1.4.0 与 v1.4.1 之间的参数变更（v1.4.1 加大 NET → 384KB），也可能是本手册基于 v1.4.0 参数编写。两说并存，等用户裁断。

## AVRCP 耳机按键控制

| 耳机按键 | 固件动作 |
|---------|---------|
| 播放 ▶ | 恢复播放（暂停后） |
| 暂停 ⏸ | 软暂停（停解码 + 清缓冲） |
| 下一曲 ▶▶ | 下一个电台 |
| 上一曲 ◀◀ | 上一个电台 |
| 停止 ■ | 停止播放 |
| 音量+ | 音量 +10 |
| 音量- | 音量 -10 |

> - 按键转发行为取决于耳机固件，差异较大。
> - 很多耳机的音量键是**硬件直控**（直接调 DAC），不发 AVRCP — 用 `vol` 命令调 ESP32 端音量。
> - 暂停为"软暂停"：停解码并清 PCM 缓冲，保持 A2DP 连接；恢复时重新拉流（几秒延迟）。

## FAQ 摘录

| 问 | 答 |
|----|-----|
| 开机后耳机不自动连接？ | 确认耳机开机未被占用；`status` 看蓝牙；`scan` 重扫；仍不行 `clear` 重来 |
| 耳机音量键没反应？ | 大概率硬件直控，发 `avrcdiag` 看日志有无事件 |
| 电台速度/音调不对？ | v1.1.0 已修 32k→44.1k 重采样与 48k 直发 |
| WiFi 改密码怎么更新？ | `wif 新SSID 新密码`，重启 |
| 央广/国广卡顿？ | v1.4.0 新增 TsDemux；CDN 不响应时仍会卡顿 |
| 为什么不支持 HTTPS？ | v1.4.0/1.4.1 受限于 mbedTLS in buffer 5120B 硬限制，用 HTTP 源 |
| 段边界偶发跳帧？ | v1.4.0 已尽量消除，TS 容器 HLS 段边界偶发无法完全消除 |

## 支持的音频格式（v1.4.1）

| 格式 | 支持 | 说明 |
|------|------|------|
| HTTP MP3 | ✅ | 蜻蜓 FM 等 |
| HTTP AAC | ✅ | 喜马拉雅 HLS AAC、国际 AAC |
| HTTP m3u8/HLS | ✅ | CNR/CRI TS 容器（TsDemux 解复用） |
| HTTPS | ❌ | 暂不支持（mbedTLS buffer 限制） |

> ⚠️ 此与软件说明书描述"HTTPS ✅"不一致。软件说明书称 v1.4.0 起支持 `WiFiClientSecure` + `setInsecure()` 跳过证书验证，本用户手册写"暂不支持"。按 AGENTS.md 规矩，两说不覆盖，并排等用户裁断。
